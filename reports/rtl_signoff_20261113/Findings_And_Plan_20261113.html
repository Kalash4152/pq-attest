2. All findings

2.1 Design and firmware findings

IDSeverityFindingWhereEffect today
D-01High (scope)Only the first 64 bytes of tile 3's firmware are measured, and they hold just two jumps and padding. The program itself is not measured.demo_fw_v2.S lines 3-6; window length 64A changed program with the same first 64 bytes passes attestation. Recorded earlier as a known limitation.
D-02High (demo)The firmware's two waits for a button run out and jump to FAIL.demo_fw_v2.S lines 59-66, 83-90The board shows a false FAIL after roughly 2.5 to 4.5 minutes without a button press (estimate).
D-03Medium (latent)The network interface can free a request slot in the same cycle its late response arrives.noc_network_interface_p7_i9.sv 765-770, 823-826Needs a response exactly 16,384 cycles late; the measured worst case is 459 cycles. Not reachable today.
D-04MediumA data packet sent to tile 4 during verification makes attestation fail.pq_rot_verifier.sv 106-115Denial of service only, and only through the untrusted port, which is tied off on the board.
D-05MediumThe memory front end ignores a request that arrives while it is busy.pq_noc_subsystem_p7_i9.sv 313Cannot happen in this build (one request at a time, one authorised tile).
D-06Medium (scope)The processor may execute code from its writable data memory.addr_decode.sv 231The demo firmware does not do this; it weakens the "only measured code runs" argument.
D-07LowA grant arriving in the same cycle as a failure leaves the tile authorised until the following revoke.noc_attest_gate.sv 39, 47Short, bounded window.
D-08 to D-11Low (latent)Four corner cases in the hash and key blocks (full final block, oversize request, context length 15, a start lost in one state).SHA3_PAD.sv 17; pq_measurement.sv; pq_kdf.sv; kmac_128_xp_a5.svAll blocked by checks in the parent block. Matter only if the blocks are reused elsewhere.
D-12LowA signal is used before it is declared.SHA3_256_xp.sv 70Vivado accepts it; an ASIC tool may reject it.
D-13 to D-15LowSelf-addressed packets, clear-versus-event ordering in two counters, small UART and error-code behaviours.VariousCosmetic or unreachable.

4. Items not built from the original proposal

ItemWhy not builtRecommendation
Second board and physical attacker linkThe spoofed-tile case is exercised through an on-chip injection port in simulation; effort went to the two processor tiles.Do not build two boards. If hardware attack evidence is needed, use C9.
NTT, ML-KEM, ML-DSA (post-quantum signatures)Scoped out on 6 November: the protocol uses symmetric KMAC128. A signature engine is a large separate block.Future work. Keep the wording "symmetric, hash-based; signatures not implemented".
Attestation of every tileOne attested and one refused tile demonstrate the mechanism; each extra attested tile costs about 13,000 LUT.Do not build. State that the mechanism is per-tile.
Continuous (timed) re-attestationRevision 9 chose start by the root of trust or a button.Optional (C8). Not needed for the paper.
Formal proof, side-channel protection, random number generatorOut of scope by decision; no formal tool on this machine.Limitations. Formal proof of two or three small properties is a good later addition if the college has the tool.
