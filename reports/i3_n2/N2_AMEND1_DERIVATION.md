## Bench changes (two, both in the include)

1. **`idle_source(t)`** returns `(pattern==1 || pattern==2) && destination(t,0)==t`. The generator guard becomes
   `generation_on && cyc<GEN_CYCLES && cyc%period==t%period && !idle_source(t)`. An idle source never increments
   `offered`, never draws from its LCG and never queues a record; its PERF line prints `offered=0`.
   - transpose: `destination = 2*(s%3)+s/3`, so 0→0 and 5→5; idle {0, 5}.
   - hotspot: `destination = 2`; idle {2}.
   - uniform (`d>=source → d++`) and neighbor (no fixed point) are never idle.
2. **POINT verdict.** `vd` is set by if/else (`"OK"` or `"FAIL"`) instead of the ternary `errors==e0?"OK":"FAIL"`.
   XSim widened that ternary of unequal-length string literals to 4 characters, printing `verdict=  OK`.
   The judge is unchanged.

**Check-count proof.** `grep -n "check(" scripts/perf_bench_body.sv.inc` gives 28 lines before and after. With line
numbers stripped, the two lists are textually identical (`diff` empty). The edits add no `check()` call and alter no
condition of an existing one, so every CHECKS total is unchanged: perf 393 = 1 + 28×14, controls 15, N-7.5 18 / 19 / 20.

## perf_m0 / perf_m1 point accounting (MAC0 and MAC1 identical)

Per source and point: offers = 2176/period (2176 = 2^7·17, so every period divides it); queued = min(offers, 256).
Point: offered = active × offers, queued = active × min(offers, 256), cap_drops = offered − queued; accepted = injected =
delivered = responses = mem_accepted = queued (every memory write gets one response).

## perf_ctrl_stall (hotspot 1/16, tile 2's memory service stops at cycle 512)

- 5 active sources (0, 1, 3, 4, 5) × 136 offers = **offered = queued = 680**, cap_drops 0 (was 816, 6 sources).
- After cycle 512 every response at tile 2 is withheld (`resp_eligible`). Each active source fills both NI slots and
  then presents a slot-blocked request. Tile 2 generates nothing, so `ds[2]=0`, its queues are empty and
  `slot_busy[2]=0`.
- Liveness line (`mask_of`, `liveness_line`):
  - `first_pending_tile=0`
  - `ds_mask=3b queue_mask=3b slot_mask=3b` (bits 0, 1, 3, 4, 5; was `3f`)
  - `resp_backlog_mask=04` (only tile 2 owes responses; unchanged)
  - `inflight=0`
- In-flight before the stall is at most 10 requests (5 × 2 slots, was 12), so the monitor still fires before cycle
  2176 and `drain_cycles=0`.
- Failing checks are unchanged: PERF_ACCEPTED, PERF_RESPONSES, PERF_IDLE_AFTER_DRAIN, PERF_BOUNDED_DRAIN and
  PERF_NO_LIVENESS. ERRORS = 1 (LIVENESS_FIRED) + 5 = **6**; CHECKS = **15**.
