2.2 Network constants (from NOC_PKG.sv)

  • Mesh and tiles: 3 x 2 mesh (MESH_X 3, MESH_Y 2), 6 tiles; tile number = y x 3 + x.
  • Flits and buffers: 32-bit flits; 3 virtual channels, each FIFO 4 flits deep; 5 router ports.
  • Routing: XY.

Tiles:

  • 0 CPU0 (0,0)
  • 1 CPU1 (1,0)
  • 2 MEMORY (2,0)
  • 3 CRYPTO (0,1), the attested tile
  • 4 ROT (1,1), the Root of Trust and verifier
  • 5 SPOOF (2,1), the untrusted injection port

HEAD flit (32 bits, MSB first):

  • Coordinates: dest_x[3], dest_y[3], src_x[3], src_y[3];
  • Type and length: msg_type[4], length[5];
  • control[11], meaning by type:
    • memory write: wstrb = control[10:7];
    • memory response: err = control[10];
    • attestation: status = control[10:7].

2.4 Authorization rules (R7.4, contract Q2 / F4)

  1. Attested tiles. Only tiles 3 and 4 are attested.
    • Tiles 0, 1, 2 and 5 cannot send control types. Their network interface raises tx_error.
    • A control packet that reaches tiles 0, 1, 2 or 5 is dropped (reason 8).
  2. Data sending. A tile may send data types (0-3) only while it is authorized:
    • tile 3 becomes authorized after a GRANT with status 1 from the RoT, and loses it on REVOKE, failure or timeout;
    • tiles 0, 1, 2 and 5 are never authorized; their gates refuse their data;
    • the RoT (tile 4) is always allowed.
  3. Memory write. Committed only if the source is authorized in the cycle of the final data word. Otherwise there is no commit, the fault counter increments, and the response is suppressed (the requester times out).
  4. Memory read. The response is offered only if the source is still authorized when the response HEAD is first offered. Otherwise it is suppressed, never zero-filled.
  5. Self-pairs. LOCAL -> LOCAL (a tile sending to itself) is illegal: 30 legal ordered pairs.
  6. Address map. Remote address 0x2T00_0000, with T = address[27:24]. The shared memory is 0x2200_0000 + offset (decision C-5). The RTL stand-in still checks the old 0x8 prefix until Lane 1 increment I-6, so take the legal window from a configuration value, not a constant.
  7. Revocation latency. REVOKE must de-authorize tile 3 within 1,500 cycles (the signed bound); 486 cycles are measured today.

Step 4: P7 authorization model (fixes G4)

Do: encode rules 1-5 of section 2.4 as a pure Python model with an explicit state: authorized tiles, GRANT / REVOKE events, and the cycle of the final write word or the read-response offer. Every generated scenario carries its expected outcome:

  • delivered;
  • refused at the source gate;
  • dropped at the receiver (reason 8);
  • write suppressed;
  • read suppressed.

Done when: unit tests cover each of the following, including its negative case:

  • control 4 -> 3 OK, and control from 0 / 1 / 2 / 5 refused;
  • data from tile 3 before GRANT refused, and after GRANT delivered;
  • REVOKE between request and final data word means no commit;
  • REVOKE before the read response offer means suppressed;
  • RoT always allowed.

Step 8: Bridge oracle (TMEM bus <-> network)

Do: a Python model of the Lane 1 bridge that turns the RISC-V tile bus (TMEM: request, address, write data, byte enables, read data, error) into network packets and back:

  • address 0x2T00_0000 -> destination tile T;
  • byte enables -> control[10:7];
  • a write -> MEM_WR_REQ (3 flits); a read -> MEM_RD_REQ (2 flits);
  • a response with err, a refusal (tile not authorized), or a timeout -> tmem_err.

Its key check: exactly one network request per bus request. The RISC-V lane had a bug that issued every request twice.

WAIT: the exact signal names, the timeout value and the refusal behaviour come from the Lane 1 integration contract, expected 2-8 Nov. Build the model now with these as parameters.

Done when: the model and its tests exist; it flags a duplicated request; it is parameterised by the contract values.

Step 9: Integration-demo oracle

Do: the expected event trace and accounting for the demo:

  1. the CPU at tile 3 requests attestation;
  2. CHALLENGE 4 -> 3, RESPONSE 3 -> 4, GRANT 4 -> 3;
  3. a write and read-back at 0x2200_0100 succeed;
  4. the CPU at tile 0 tries the same write and gets a bus error, with no commit;
  5. REVOKE: tile 3 is de-authorized within 1,500 cycles, and its next access gets a bus error.

Output the expected counters: memory commits, memory faults, gate faults per tile, and grants and revokes.

WAIT: the final tile placement (proposed: CPUs at tiles 3 and 0) is a pending Lane 1 decision; keep it a parameter.

Done when: the trace and counters are generated from the step 4 model, with a test per phase.
