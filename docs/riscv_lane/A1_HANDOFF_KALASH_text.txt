4. Root-cause hypothesis and adapter behavior
The suspected A1 defect is in rtl/picorv32_adapter.sv. The adapter uses IDLE, REQUEST and RESPONSE. In RESPONSE, on local_rvalid_i or tmem_rvalid_i, it registers mem_ready_q &lt;= 1 and state_q &lt;= IDLE on the same edge. PicoRV32 samples the registered ready pulse on a later rising edge. During the interval before the CPU lowers or changes mem_valid/address, the adapter is already IDLE and can see the old request again.
The intended guard in the IDLE capture path is:
if (mem_valid_i &amp;&amp; !mem_ready_q) begin
In the uploaded working-copy adapter this behavior is factored into:
wire capture_attempt = (state_q == IDLE) &amp;&amp; mem_valid_i;\nwire capture = capture_attempt &amp;&amp; !mem_ready_q;
The sequential IDLE branch captures only when capture is true. The expected edge behavior, to verify against the exact PicoRV32 RTL, is: (1) response edge: adapter schedules ready=1 and IDLE; (2) next edge: CPU samples ready while the old valid may still be high, adapter sees ready_q=1 and suppresses capture; (3) after that edge CPU may lower valid or present the next compressed fetch address; (4) following edge, with ready_q cleared, a still-valid new request can be captured. Compressed-ISA back-to-back fetches must be explicitly tested; do not assume valid must go low between all transfers.
The guard is plausible and initial CPU traces show progress past 0x12C, but this is not sufficient to certify correctness.

6.3 Assertion issue in current local version
The screenshot of the local adapter after the edit showed:
wire capture_attempt = (state_q == IDLE) &amp;&amp; mem_valid_i;\nwire capture = capture_attempt &amp;&amp; !mem_ready_q;\n...\nif (!reset_i &amp;&amp; mem_ready_q &amp;&amp; capture) begin\n    $error(...);\n    $fatal(1);\nend
This check is tautological: capture is defined to include !mem_ready_q, so mem_ready_q &amp;&amp; capture can never be true. It will not independently detect a violation. Replace it with a meaningful assertion on the actual sequential capture event or structure the logic so the property checks the capture enable independently. The specification’s intent is no accepted capture while ready is high, not no capture_attempt.
