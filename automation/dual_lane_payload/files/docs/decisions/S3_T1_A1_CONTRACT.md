# S3 contract: T1 Keccak select replication + A1 shared tile-3 Keccak core + A6 single-block measurement SHA3 + A5 KMAC state-copy removal (each part written before its RTL)

- **Approved:** Kalash 2026-11-02, Step B choice "T1 + A1, then A2".
- **Source study:** reports/STEP_A_AREA_TIMING_20261102.md.
- **A2:** the tile-4 KMAC merge is NOT in this contract. It changes signed bounds, so its bound proposal is a separate
  document and a hard stop for Kalash.
- **Wire format, M-F1 revision, device, clock and budget:** unchanged. No protected file is written.

## 1. T1: replicated Keccak FSM select (all four engines)

- **Problem (registered P7 routed, run d99f256c):** in each `keccak_f1600`, the one onehot `fsm_state` bit drives the
  next-state select of all 1,600 `state_reg` bits (fanout 1,618). This gives 121 of the 123 endpoints within 0.5 ns, with
  97 % of the path in routing.
- **Change:** a variant `rtl/dual_lane/pq_keccak_f1600.sv`, same module name `keccak_f1600`, same ports, generated from
  the production `pq_keccak_f1600.sv` by `scripts/prepare_s3.py`.
  - It adds `fsm_rep[25]`: registered copies of the 2-bit `fsm_state`, one per 64-bit lane, marked `(* keep = "true" *)`
    so synthesis does not merge them.
  - Each copy takes the same next value as `fsm_state` in the same cycle, including reset and the defensive default.
  - Each lane's `state_reg` update uses `case (fsm_rep[lane])` with the same three branches as the original.
- **Invariant T1-I1, cycle identity:** for every input sequence, `state_out`, `busy`, `done`, `round_valid` and
  `round_index` are identical to the original in every cycle. Consequences: every registered digest, count and cycle figure
  is unchanged.
- **Invariant T1-I2, replica agreement:** `fsm_rep[k] == fsm_state` in every cycle after reset. An RTL procedural check
  (`$error`, translate_off) reports any disagreement.
- **Cost:** +50 FF, about 0 LUT (each lane's select LUT already exists, now fed by a local copy).

## 2. A1: one Keccak core shared at tile 3 by the KMAC (KDF + tag) and the measurement SHA3

**Basis.** The endpoint controller runs `S_KDF_*` -> `S_MEAS_*` -> `S_TAG_*` strictly in sequence
(rtl/dual_lane/pq_attest_protocol.sv:412-664). KDF and tag already share one kmac128 (`pq_kmac_share`, B-3). The
measurement's `sha3_256` has its own `keccak_f1600` that is never active at the same time as that kmac128.

**New files** (all generated by `scripts/prepare_s3.py`, exact-anchor edits, provenance in `rtl/dual_lane/s3_provenance.json`):

| File | Module | Made from | Edit |
|---|---|---|---|
| `kmac_128_xp.sv` | `kmac128_xp` | `NOC_PQATTEST.srcs/sources_1/new/kmac_128.sv` | internal `keccak_f1600` instance replaced by a permutation port `p_start`, `p_state_in` (out), `p_state_out`, `p_busy`, `p_done` (in) |
| `SHA3_256_xp.sv` | `sha3_256_xp` | `NOC_PQATTEST.srcs/sources_1/new/SHA3_256.sv` (protected; read only) | same permutation port |
| `pq_kmac_share_xp.sv` | `pq_kmac_share_xp` | `rtl/dual_lane/pq_kmac_share.sv` | instantiates `kmac128_xp`; passes the port through |
| `pq_measurement_xp.sv` | `pq_measurement_xp` | `rtl/dual_lane/pq_measurement.sv` | instantiates `sha3_256_xp`; passes the port through |
| `pq_attest_protocol_s3.sv` | `pq_attestation_controller` | `rtl/dual_lane/pq_attest_protocol.sv` | the two `_xp` engines plus ONE `keccak_f1600` with an owner register |

**Shared-core rules:**
- **R1 (request):** `start = kmac_p_start | meas_p_start`; `state_in = meas_p_start ? meas_state_in : kmac_state_in`.
  The core samples `state_in` only in its start cycle (keccak_f1600 contract).
- **R2 (owner):** `owner_q` is set to MEAS on `meas_p_start` and to KMAC on `kmac_p_start`, only when the core is IDLE;
  it is held otherwise.
- **R3 (isolation):**
  - `p_done` goes to the owner only: `kmac_p_done = done && owner_q == KMAC`, `meas_p_done = done && owner_q == MEAS`.
  - `state_out` is wired to both, but both wrappers capture it only inside `if (keccak_done)` (kmac_128.sv:449/479/509,
    SHA3_256.sv:218-235). So the non-owner never captures the other owner's state, including the key-derived state that
    the KDF leaves in the core.
- **R4 (busy):** `p_busy` is the core's busy, broadcast to both (a start into a busy core is a contract violation, R5).
- **R5 (exclusivity), checked by RTL procedural `$error` and by the new bench:** never `kmac_p_start && meas_p_start`
  in one cycle; never a start while the core is not IDLE.

**Invariants:**
- **A1-I1 (digests):** every response equals the registered result, i.e. the s8 golden vectors, endpoint unit and system
  benches, unchanged counts.
- **A1-I2 (latency):** the permutation path keeps the same cycle count (combinational request mux, registered owner used
  only for `done` routing). So n2p7_rtt is expected to print the same round trip (1,204 idle). This is reported, not
  asserted; any change is recorded as a finding.
- **A1-I3 (isolation):** R3 holds every cycle (new bench).

## 2a. A6: single-block measurement SHA3 (added 2026-11-02, Kalash approval of the S3 package, before its RTL)

- **Basis:** `MEASURE_MSG_MAX_BYTES = 135` < `RATE_BYTES = 136` (pq_measurement_pkg.sv:53, SHA3_PKG.sv:8), and
  `req_len_ok` rejects longer requests (pq_measurement.sv). So every measurement is one SHA3 block absorbed into the all-zero
  state.
- **Change:**
  - `pq_measurement_xp` writes the SHA3 padding itself:
    - `msg_block_q` is accepted with bit 1087 set;
    - in the existing end cycle (`build_idx_q == valid_bytes`) the byte decoder writes the domain byte at that index:
      `0x86` when the index is 135 (domain and end bit share the byte), else `0x06`.
  - `sha3_256_xp` drops `sha3_pad`, `sha3_absorb` and its 1,600-bit `state_reg`. The core input is the block in lanes
    0..16 (lane i <- block[64i +: 64] at [i%5][i/5], the sha3_absorb mapping) with zeros elsewhere, and the digest is
    serialised from `p_state_out` on its own done.
- **Invariant A6-I1:** the block equals `sha3_pad(msg, valid_bytes = req_len, is_final = 1)` for every legal length, so
  the digest is unchanged.
- **Invariant A6-I2:** same FSM (IDLE -> KECCAK_START -> WAIT -> DONE), so the latency is unchanged; the bench checks it
  exactly.
- **RTL check:** `start && !is_final` -> `$error` (single-block contract).

## 2b. A5: KMAC wrapper state copy removed (added 2026-11-02, before its RTL)

- **Basis:** kmac128 reads its `state_reg` copy only as the absorb input (BLOCK0..2) and in SQUEEZE. That copy equals:
  - zero in BLOCK0;
  - the core's `state_out` from the previous permutation in BLOCK1, BLOCK2 and SQUEEZE. The core holds `state_out` from
    `done` until its next start (keccak_f1600 contract), and nobody starts the core inside a KMAC message (E3 / E4
    unshared; E1 shared under A1 R5, sequential phases).
- **Change:** the absorb base is `(ctrl_state == KMAC_BLOCK0) ? 0 : keccak_state_out`; the squeeze reads `keccak_state_out`;
  `state_reg` and its writes are deleted. This applies to both `kmac128_xp` (E1) and a same-name variant
  `rtl/dual_lane/kmac_128.sv` (internal core: E3, E4), which replaces the production `kmac_128.sv` in S3 lists.
- **Invariant A5-I1:** cycle-identical and the same tag for every input; the KATs check it.

## 5. Re-adjudication record (2026-11-02, after run dual_lane_10_20261102_183915_69aa2d1b)

- **The result:** `s3_mut_state_in` was judged **INVALID**: "unrelated failure in mutant run: [FAIL] G00_TAG". That record
  stands and is not relabelled.
- **Cause:** a specification error in this contract, not a design finding. The tag is computed over the measurement
  (pq_attestation_tag_xk `.measurement(measurement)`), so a wrong measurement necessarily also fails `G..TAG` and
  `G..FULL_RESPONSE`. The frozen scope (the oracle alone) could never contain that consequence.
- **New record:** `s3_mut_state_in_r2`, same mutant `s3p_state_in_kmac`, same bench and count (95):
  - oracle `^\[FAIL\] G\d\d_MEASUREMENT`;
  - kill_scope `^\[FAIL\] G\d\d_(MEASUREMENT|TAG|FULL_RESPONSE)$`: only the measurement and the fields computed from it.
    Any other failing check, a timeout or a fatal is still INVALID.
- **Increment list:** `s3_mut_state_in` leaves it (its job definition and INVALID record are kept); `s3_mut_state_in_r2`
  joins it. Frozen here before its first run.

## 6. Amendment after the first S3 synthesis (2026-11-02, run dual_lane_10_20261102_192324_9cde1d22)

**Measured (post-synthesis, Vivado 2024.1, xc7a100t, same flow as the registered P7):**
- total 40,247 LUT / 27,932 FF, against the registered post-synthesis 44,412 / 36,101;
- endpoint 16,568 -> 10,819 LUT (T1 + A1 + A6 + A5 at tile 3);
- **L2 engine kmac 5,937 -> 6,727 LUT and verifier kmac 6,824 -> 7,618 LUT (+790 / +794), while their FF fell by
  1,660 / 1,579.**

**A5 is WITHDRAWN.** Removing the 1,600-bit wrapper copy moves its zero / hold function from the flip-flops' free
reset and enable pins into a real 1,600-bit select LUT (`BLOCK0 ? 0 : state_out`). That LUT cannot merge with the absorb XOR
across the `-flatten_hierarchy none` module boundary, so kmac128's own logic rose from 934 to 1,729 LUT per engine. LUT is
the budget and FF is not, so A5 costs about +2.4k LUT over three engines. The estimate in STEP_A_FULL_SCOUT (-1.3 to -1.6k
LUT per engine) was wrong in sign.

The rest of the change:
- `kmac128_xp` keeps the A1 permutation port only;
- `rtl/dual_lane/kmac_128.sv` is deleted, and S3 lists keep the production kmac_128.sv;
- job `s3_mut_absorb_zero` leaves the increment. Its record in run dual_lane_10_20261102_190244_e66e835d (KILLED) stays as
  history of a withdrawn change.

**The P&R job stopped at the post-synthesis structural check, as INVALID (not a design failure).** The child-engine check in
scripts/d4_crypto_ooc_child.tcl expects the pre-S3 hierarchy (a Keccak inside each wrapper, SHA3 pad / absorb). Following the
B-3 precedent (structure-aware rows when `controller/u_pq_kmac_share` exists), when `controller/u_perm` exists the S3 rows
require:
- kdf_xk, tag_xk;
- pq_kmac_share(_xp), its kmac128(_xp) with absorb and encode, and no Keccak inside the wrapper;
- **`u_perm` keccak_f1600 and `u_perm/u_keccak_round`;**
- pq_measurement(_xp) and its sha3_256(_xp).

Every real engine must still be present and of the right module. Only the removed blocks (by design: A1 moved the Keccak,
A6 removed pad / absorb / Keccak from the SHA3) leave the list.

**Expected after the amendment** (estimate): about 37.8k LUT post-synthesis.
