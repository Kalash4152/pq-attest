# T4 contract: cycle-identical lookahead routing in a router variant (written before any T4 RTL, 2026-11-05)

Kalash, 2026-11-05: "Start lookahead router" (after S4 gate FAIL, reports/S4_GATE_20261104.md, and the hierarchy study
reports/s4_hier_study_20261105/HIER_STUDY.md showed flow settings cannot make the S4 area timing-safe). Plan item T4 of
docs/proposals/S4_AREA_TIMING_PLAN_20261104.md.

## 1. What changes

The protected router files are NOT edited. Variants generated by `scripts/prepare_t4.py` from pinned sources (hashes in
`rtl/dual_lane/t4_provenance.json`), exact-anchor edits that must match once:

| Variant | Module | From | Change |
|---|---|---|---|
| `rtl/dual_lane/noc_fifo_la.sv` | `noc_fifo_la` (new name) | `NOC_FIFO.sv` | stores `{route_valid, route_port}` beside every flit, computed at WRITE time by `noc_xy_routing(cur_coord, dest(wr_flit))`; read side returns the stored route, or `noc_xy_routing(cur_coord, dest('0))` when empty (exactly what the original computes from its `'0` head) |
| `rtl/dual_lane/noc_router_datapath_la.sv` | `noc_router_datapath` | `NOC_DATAPTAH.sv` | the 15 input-VC FIFOs become `noc_fifo_la`; new input `cur_coord`, new outputs `head_route_port[15]`, `head_route_valid[15]` (index = `make_input_vc`) |
| `rtl/dual_lane/allocator_la.sv` | `NOC_ALLOCATOR` | `allocator.sv` | the 15 `noc_xy_routing` instances on the FIFO heads are replaced by the stored route inputs `head_route_port` / `head_route_valid` |
| `rtl/dual_lane/noc_router_la.sv` | `noc_router` (same name and ports; the protected mesh instantiates it unchanged) | `noc_router.sv` | wires `current_coord` and the stored routes from the datapath to the allocator |

`NOC_FIFO.sv` (eject FIFO, NIs) and `NOC_XY_ROUTING.sv` stay in the list unchanged. The T4 list = the S4 list with
`allocator.sv`, `NOC_DATAPTAH.sv`, `noc_router.sv` swapped for their variants plus `noc_fifo_la.sv`; no variant shares a
list with its original.

## 2. Invariants (why it is cycle-identical)

- `noc_xy_routing` is a pure function of `(current_coord, dest_x, dest_y)`; `current_coord` is a constant per router
  (driven by the protected mesh). For every entry, stored route = `xy(cur, dest(stored flit))`, so at every cycle the
  allocator variant's route inputs equal what the original computes from `head_flit`. All other allocator inputs, all
  state and all outputs are unchanged: same grants, same cycles, same flits.
- No wire, flit-format, latency, credit, signed-bound, clock or device change. Not an M-F1 revision (nothing on a wire changes).
- Cost: 4 extra LUTRAM bits per input-FIFO entry, route logic moves to the write side (after the link register).

## 3. Jobs (counts frozen here, before the first run)

Selection `t4`:
- `t4_variant` (python `scripts/check_t4.py`, marker `T4_VARIANT: PASS`): the variants equal their generation.
- `t4_router_equiv` (new bench `sim/t4/tb_t4_router_equiv.sv`): the original `noc_router` and an equivalence copy of the
  variant (`noc_router_t4eq`, same generator, module names suffixed, `sim/t4/`) at each of the 6 mesh coordinates, driven
  in lockstep by the same credit-respecting random traffic (legal heads to every destination incl. off-mesh coordinates,
  bodies, tails, head-tails, all VCs); every output compared every cycle. CHECKS = 6 coordinates x 2 (`EQ_<n>_OUTPUTS`
  zero mismatches over 20,000 cycles; `EQ_<n>_TRAFFIC` at least 2,000 flits delivered and every output port used) = 12.
- Every S4 job (`s4_*` simulation, non-mutant) re-run on the T4 list, counts unchanged, ids `t4_<s4 id without s4_>`,
  plus their Python dependencies.
- Controls: `t4_mut_route_stale` (the variant FIFO returns the route of the entry AFTER the head) on `t4_router_equiv`, oracle
  `^\[FAIL\] EQ_\d_OUTPUTS`; `t4_mut_route_coord` (route computed with x and y swapped) on `t4_router_equiv`, same oracle.

Selections run alone after `t4`: `t4_pnr` (OOC all ports), `t4_soc_pnr`, `t4_n13_secure`, `t4_n13_insecure`, all with the
S4 flow (F1 + F2) on the T4 list.

## 4. Acceptance

All `t4` jobs PASS_FRESH (controls KILLED); all four implementation jobs PASS their gates (WNS / WHS >= 0, N-13 gate
unchanged, LUT <= 47,550). Margin target (reported, not a gate): OOC WNS >= +0.2 ns. If the scratch measurement before
registration shows no material WNS gain, T4 stops there and is reported. HARDWARE_VALIDATED=NO, SOC_INTEGRATION_COMPLETE=NO,
FORMAL_PROOF=NO.

## 5. Outcome of the scratch measurement (2026-11-05): parked

Scratch P&R (S4 flow, all ports, OOC; vivado_sim/_t4, copied to reports/s4_m1_study_20261105): 31,172 LUT, WNS +0.016 ns
(S4 without T4: -0.018), 27 levels. The worst path is now the two-stage allocator + crossbar select (78 % route); the XY
compare was a small part. Not a material gain (sec. 4), so T4 stops here: no jobs registered, variants and generator kept
for reference. Timing is recovered by S4-F3 instead (S4_AREA_CONTRACT.md sec. 6).
