### N2.1 — Blueprint (write the plan document first)

**TB structure** (`tb_noc_perf.sv`, top `tb_noc_perf`):
- DUT: `noc_mesh_3x2` + 6 × `noc_network_interface`, exactly as in `tb_noc_n81.sv`. Reuse its GN generate block, `send_msg`, and the RX models.
- **Traffic generator per tile** (`tg[t]`), deterministic LFSR stimulus with the seed as a parameter (no `$urandom(seed)`):
  - **Pattern:** uniform random, transpose, hotspot (all tiles → MEMORY), neighbour.
  - **Injection rate:** offered load λ ∈ {1/64, 1/32, 1/16, 1/8, 1/4, 1/2, 1} packets per cycle per tile, via an LFSR threshold.
  - **Message mix:** MEM_RD_REQ 2 flits, MEM_WR_REQ 3, ATTEST_CHALLENGE 6, ATTEST_RESPONSE 17 (MAC off). Allocate transaction tags with `N_OUTSTANDING=2`. Tiles *respond* to memory requests in this TB: MEMORY answers with RD/WR_RESP, which is what makes the request/response classes exercise VC separation.
  - A packet is **generated** at `t_gen` (tile queue), **injected** at `t_inj` (NI HEAD handshake) and **delivered** at `t_del` (destination NI accepts the terminator).
- **Monitors** (read-only hierarchical probes, as in `tb_noc_n81`):
  - per-link flit count (utilization);
  - per-(router, input VC) FIFO occupancy histogram;
  - credit-stall cycles (`grant_valid && !transfer_valid` per output);
  - eject FIFO occupancy;
  - NI TX_FILL cycles (store-and-forward cost).
- **Independent scoreboard:** expected packets are keyed by (src, dst, seq). Payload words come from `pay_word(seed, i)` and are checked on delivery. Every generated packet must be delivered exactly once, in order per (src, dst, VC). This is what upgrades N-6/N-8 toward `sim-verified`.
- **Output:** one CSV line per packet on stdout (`PKT,src,dst,msg,len,t_gen,t_inj,t_del`), plus per-run summary lines (`LINK`, `OCC`, `STALL`). The Python script builds the plots and tables.

**Measurements:**

| Metric | Definition | Expected shape |
|---|---|---|
| Zero-load latency per hop count | t_del − t_inj at λ = 1/64, by Manhattan distance 1–3 | linear: a + b·hops. **Measure a and b; do not assume them.** (LINK_PIPE adds 1 cycle per hop, EJECT_PIPE adds 1) |
| Store-and-forward cost | t_inj − (request accept) against payload n | ≈ T_fill = n cycles (N-8.1 sec.8 formula) |
| Latency vs offered load | mean, p95 and max of t_del − t_gen per pattern | knee = saturation |
| Accepted throughput | delivered flits per cycle per tile vs λ | plateau at saturation |
| Per-VC fairness | throughput split REQ/RESP/ATT under hotspot | reveals FD-1 per-port-lock effects |
| Credit-stall fraction | stalled cycles / active cycles per output | where credits limit (I-1: RTT 4 = depth 4) |
| Containment cost | repeat uniform traffic with a malicious SPOOF (always blocks), W = 16/64 | throughput loss vs W; must stay bounded (links to N-8.1 claim 2) |

**Acceptance:**
- Scoreboard 0 errors in every run.
- Zero-load latency is linear in hops (R² ≈ 1).
- No deadlock at any λ; a drain check follows each run.
- All numbers reported with provenance (Verilator build / XSim, RTL commit, W, MAC mode).
- Run the long sweeps in **Verilator** (fast), then reproduce **2 representative points in XSim** to cross-validate. XSim is slow for sweeps.

### C1.1 — Two width conflicts found (decisions for Kalash; do not code around them)

1. **Response.** The Python response is TILE_ID 7 + EPOCH 10 + NONCE 16 + MEASUREMENT 32 + TAG 32 = **97 B = 776 bits**. M-F1 freezes ATTEST_RESPONSE at **16 payload flits = 512 bits**.
2. **Challenge (new finding).** The request is TILE_ID 7 + EPOCH 10 + NONCE 16 = 33 B = 264 bits. Even with TILE_ID implied by the NoC header destination, EPOCH + NONCE = **26 B = 208 bits**. M-F1 freezes ATTEST_CHALLENGE at **5 payload flits = 160 bits**. It does not fit.

**Options.** Each has a cost; the recommendation is marked.

| id | Change | NoC impact | Protocol impact | Verdict |
|---|---|---|---|---|
| **Q-C** | ATTEST_CHALLENGE payload 5 → **7 flits** (EPOCH 80 + NONCE 128 = 208 bits, 16 pad bits). Length 8 (MAC off) / 12 (MAC on) | M-F1 **rev 5** (`message_payload_flits(ATTEST_CHALLENGE)` 5 → 7). TX buffer 16 ≥ 7, so no NI change. N-8.1 evidence is unaffected (its long packet is the RESPONSE) | none | **Needed under any response option** |
| **R-B** | ATTEST_RESPONSE stays **16 flits = MEASUREMENT (32 B) ‖ TAG (32 B)**. TILE_ID comes from the NoC header src; the verifier supplies EPOCH/NONCE from its own outstanding-challenge table | **None.** Keeps M-F1 sec.4 and all N-8.1 evidence (17-flit packet) | Python `AttestationResponse` must be built by the verifier from (header src, stored epoch, stored nonce, measurement, tag). **Explicit protocol change, recorded, not silent.** Security: the tag already binds tile_id, epoch and nonce, so the echoed fields add no authentication; the verifier needs per-tile challenge state anyway for freshness | **Recommended** |
| R-A | ATTEST_RESPONSE 16 → **25 flits** (800 bits, 24 pad). Length 26 / 30 (the 5-bit length field allows 31) | M-F1 rev 5. NI `TX_BUF_DEPTH` 16 → 25, `MAX_PACKET_FLITS` 21 → 30. **Redo the N-8.1 storage analysis and rerun the full SPOOF matrix** (P_A becomes 26/30 flits) | none | Fallback if Kalash wants the Python wire format kept verbatim |
| R-C | Split into 2 packets | Reassembly and ordering state in the NI or tile | messy | Rejected |

## 5. Crypto lane — Stage C2: tile attestation endpoint + crypto OOC synthesis (S-8.2 / D4)

**Goal:** connect Stage 8 to the NoC through the NI tile interface, so that an ATTEST_CHALLENGE packet arriving at a tile produces an ATTEST_RESPONSE packet back to the requester. Then synthesize the crypto lane out of context. **This depends on the C1.1 decision; the blueprint below assumes Q-C + R-B.**

### C2.1 — Architecture (write `docs/decisions/S8-2-tile-attest-endpoint.md` first)

```
         NoC  <->  noc_network_interface (M10, frozen N-8.1)  <->  pq_attest_endpoint  <->  pq_attestation_controller (Stage 8)
                   rx_head_valid / rx_payload_* / rx_ready           (NEW)                  start/done/err/response[775:0]
                   tx_valid / tx_payload_* / tx_ready
```

**Module `pq_attest_endpoint`** (new file `pq_attest_endpoint.sv`; this replaces the 0-byte placeholders).

**Ports** (exact names of the NI tile interface, from `noc_network_interface.sv`):
- Clock/reset: `clk`, `rst` (the NI is **active-high**) plus `rst_n` for Stage 8 (**active-low**). Derive one from the other inside the endpoint and document it. Do **not** change either child's reset style.
- From the NI RX: `rx_src_coord`, `rx_msg_type`, `rx_control`, `rx_head_valid`, `rx_payload_data`, `rx_payload_valid`, `rx_payload_last`, `rx_abort`, and the output `rx_ready`.
- To the NI TX: `tx_valid`, `tx_ready`, `tx_dest_coord`, `tx_msg_type`, `tx_control`, `tx_payload_data`, `tx_payload_valid`, `tx_payload_ready`, `tx_error`.
- Tile-private configuration (not from the NoC): `root_secret[255:0]`, `context_in[111:0]`, `context_len[3:0]`, `config_data[511:0]`, `config_len[6:0]`, `imem[511:0]`, `imem_len[6:0]`, `tile_id[55:0]`.
  - **OPEN:** the source of `root_secret` on the FPGA (register loaded at build time? a PUF stand-in?). State it clearly as a demo-only stand-in.
- Status: `busy`, `last_status[2:0]`, `last_error[3:0]`.

**FSM:**
1. `E_IDLE`: `rx_ready=1`.
   - A HEAD with `msg_type == ATTEST_CHALLENGE` → latch `rx_src_coord` (the reply-to) → `E_RX`.
   - Any other message type: consume and ignore; count it.
2. `E_RX`: collect 7 payload words into `chal[223:0]`, word i at `[i*32 +: 32]`.
   - `epoch = chal[0 +: 80]`, `nonce = chal[80 +: 128]`. Byte order: byte i at `[i*8 +: 8]`, which must be checked against the Python packing in C1.
   - On `rx_abort` → back to `E_IDLE` with no response. The tile must drop partial data (N-8.1 sec.7).
3. `E_RUN`: pulse `start` on the controller and wait for `done`.
4. `E_TX_REQ`: `tx_valid`, `tx_dest_coord = reply_to`, `tx_msg_type = ATTEST_RESPONSE`, `tx_control[10:7] = status code` (S8-4 table), wait for `tx_ready`.
5. `E_TX_FILL`: 16 payload words: measurement words 0..7 = `response[33*8 + 32*i +: 32]`, then tag words 0..7 = `response[65*8 + 32*i +: 32]`. Handshake on `tx_payload_ready`; the NI store-and-forward takes them into its buffer.
6. On controller `err`: send an ATTEST_RESPONSE with the status code set and **zero payload**. Or define ATTEST_RESPONSE-with-error as a separate rule in S8-5. **Decide this in the doc; do not improvise it in RTL.**

**Stall discipline** (it matters with N-8.1): the endpoint sets `rx_ready = 1` in `E_IDLE` and `E_RX`, so it **never** stalls the NI. Its RX total stall is therefore 0 against W; add an SVA for this. The TX side can take arbitrarily long; store-and-forward means nothing is in the network until the fill is complete.

### C2.2 — Verification

1. **Unit TB `tb_attest_endpoint.sv`:**
   - Drive the NI tile interface directly (no router), like `tb_ni_n81`.
   - Cases: good challenge → a response whose 16 words equal the reference chain from `tb_stg_8_ref`; challenge + `rx_abort` mid-payload → no response; a non-ATTEST message → ignored; controller error → error response; back-to-back challenges.
2. **System TB `tb_attest_system.sv`:** mesh + 6 NIs + an endpoint on CRYPTO (or on every tile).
   - The RoT tile model issues a challenge and checks the returned measurement/tag against the reference chain. This is the first end-to-end NoC attestation (the S-10 precursor).
   - Add a SPOOF run: SPOOF blocks RX while the RoT↔CRYPTO attestation runs. It must still complete (N-8.1 containment in context).
3. **Mutation:**
   - word order of the tag swapped;
   - epoch/nonce extraction offset off by one word;
   - wrong reply-to (sends to self);
   - endpoint stalls `rx_ready` on a challenge. That one should trip the NI containment and fail the test by timeout.

### C2.3 — D4: crypto lane OOC synthesis (before any whole-design resource claim)

Non-project OOC runs, same template as `scripts/n81_ni_ooc.tcl`. Tops, one run each, all with a 20 ns clock:
- `pq_kdf`, `pq_measurement`, `pq_attestation_tag`, `pq_attestation_controller`;
- `pq_attest_endpoint` (after C2.1).

Report per module: LUT, FF, LUTRAM, BRAM, DSP, WNS/WHS, and the critical path. Label everything **OOC**.

**Watch out for:**
- **Three independent `kmac128` instances** (KDF, tag, and the SHA3 inside measurement is separate). Stage 8 instantiates each engine once, so area ≈ the sum. Record whether a shared-Keccak architecture is worth it. That is a research/area trade-off note, not a change now.
- **Keccak-f round logic** is the likely critical path. If WNS < 0 at 50 MHz, the options are:
  - (a) a register between round halves (+1 cycle per round);
  - (b) run crypto at 25 MHz with a proper CDC. That is a major decision; write it up, don't do it silently.

Scripts: `scripts/d4_crypto_ooc.tcl`. Reports: `reports/d4_crypto_ooc_<date>/`.
